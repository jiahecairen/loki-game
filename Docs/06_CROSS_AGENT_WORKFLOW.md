# 多 Agent 协作流程（Claude Code ↔ Codex）与实现路线决策规则

> 适用于所有在本项目工作的 AI Agent。优先级：**质量 > 速度 > token**。

## A. 铁律
1. **同一时刻只有一个 Agent 动手**（编辑器、MCP 端口 8765、二进制资产 `.uasset/.umap` 都不可并行；二进制不可 Git 合并）。
2. 一次一个最小步骤，做完停下等用户"通过，继续"。Agent 自测不等于用户验收。
3. Git 提交需用户批准。**所有日常工作都在 `main` 一条线上轮流提交**（同一时刻只有一个 Agent 动手，所以不会冲突）。不要给每个 Agent 建长期分支：二进制资产无法合并，两条分支各改一份蓝图就会冲突，也容易让 Agent 在错误分支上干活。
4. 状态以仓库文件为准，不以聊天记忆为准。

## B. 开工流程（每个 Agent、每个新会话必须先做）
1. 运行 `bash Tools/session_start.sh`（打印当前状态、最近提交、未提交改动、MCP 端口、最近日志）。Claude Code 已配置 SessionStart 钩子自动执行；Codex 需手动执行。
2. 读 `Docs/STATE.md`（最重要，当前步骤/状态/下一步/待决定）、`Docs/05_HANDOFF.md`。
3. 若 STATE 状态为"进行中"：**先向用户汇报并核对实际改动（git diff、编辑器状态），不要盲目续做**。
4. 确认编辑器只有自己在用：若有残留 PIE 先停止；用户若同时开着另一个 Agent，先问。

## C. 收尾流程（每个小步骤结束时必须做，不能省）
1. 停止 PIE、保存所有改动的资产/关卡。
2. 追加 `Docs/01_DEV_LOG.md`（做了什么、资产路径、实测证据、未验证项）和 `Docs/02_ACCEPTANCE_LOG.md`（待用户验收）。
3. **覆盖更新 `Docs/STATE.md`**（见该文件格式）。
4. 重要经验/新资产/新限制，补进 `Docs/05_HANDOFF.md`。
5. 向用户汇报，用固定模板，并等待验收。

## D. 实现路线决策规则（每步开始前先判断，并在回复里写出"路线：C++ / MCP / 混合 + 理由"）
**判定顺序：**
1. **必须 MCP（C++ 做不到）：** 摆放/改关卡与物体、导航体积、材质、动画蓝图与动画资产引用、Sequencer、UMG 布局、导入素材、输入映射、项目设置、把类挂到人偶/网格/材质上、运行 PIE 并读数据验证。
2. **优先 C++（质量第一）：** 会被多次修改/复用/被多个资产依赖的"系统"逻辑——血量与伤害、AI 状态与感知、能力系统、检查点/失败重试、存档、数据结构；以及复杂度超过约 20 个蓝图节点、含状态机/计时/并发的逻辑。理由：可读、可 diff、可审查、可写自动测试、减少 MCP 连线出错。
3. **蓝图可接受：** 一次性、关卡专用、很小（≲20 节点）的触发逻辑；纯数据调参的蓝图子类；UI 绑定。
4. **混合是常态：** C++ 基类（系统）+ 蓝图子类（数据/资产引用）+ MCP（摆放、配置、验证）。

**质量要求（不因省时间或省 token 而降低）：**
- C++：必须编译通过（`Module Recompile LOKI` 或命令行 Build.sh，0 错误且无新增警告）→ 在编辑器里 PIE 实测并读数据 → 再交付。改了类成员变量/头文件布局，要说明热重载可能不稳，必要时请用户重启编辑器后复测。
- 蓝图（MCP）：`compilerStatus=UpToDate` 且 0 错误；复杂图用 `blueprint.lint_blueprint` 检查；有警告要解释。
- 两种路线都必须有 PIE 实测证据；不能只写"应该可以"。
- 不擅自把已通过的蓝图系统迁移成 C++；迁移需用户批准，作为单独一步（迁移前后行为需对比实测）。
- 若判断困难，选质量更稳的路线；如果两种都可行，向用户简述取舍，不要无谓提问。

## E. 交叉审查（有两个 Agent 额度时）
- 主笔完成一步后，另一个 Agent 只读审查（读代码/日志，不动编辑器），把问题写进 `Docs/STATE.md` 的"待解决/审查意见"。
- 一切改动（含 C++ 文本）都在 main 上轮流进行；二进制资产严格串行。

## F. 常见陷阱
见 `Docs/05_HANDOFF.md` 第 4、5、8 节（MCP 引脚中文名、PIE 与蓝图编辑冲突、材质 usage flag、热重载命令等）。

## G. Git 约定（给用户和 Agent）
- `main` = 唯一工作线。每个小步骤结束，经用户批准提交一次；**用户验收通过后再打标签** `sNN-accepted`（如 `s12-accepted`），用于回退。
- 推送到 GitHub 需用户批准；建议每步通过后推一次作云端备份。
- 仅"有风险的大改"（如把核心系统迁到 C++）才开临时分支 `feat/<名字>`，通过后合回 `main` 并删除。
- `codex` 分支目前与 `main` 相同，不再使用；未经用户同意不要删除，也不要让它落后后再切过去干活。
- 开工前：`git branch --show-current` 必须是 `main`（或用户指定的临时分支）。

## H. 换手话术
**用户只需说一句：「现在由你接手」。** 任何 Agent 听到后，按 `CLAUDE.md` / `AGENTS.md` 里"接手触发词"一节自动执行：跑开工脚本 → 读 STATE/交接文档 → 核对 Git 与编辑器 → 若上一位中断则核对改动 → 汇报 → 停下等用户指令。流程细节见本文件 B 节。
（上一个 Agent 还有一点额度时，可先对它说"现在收尾"：停 PIE、保存、更新日志和 `Docs/STATE.md`，提交前给用户看改动清单。）
