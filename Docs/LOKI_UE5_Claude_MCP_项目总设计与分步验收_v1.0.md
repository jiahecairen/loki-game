# 《LOKI / 洛基》UE5 + Claude MCP 项目总设计与分步验收规范

> 文档版本：v1.0｜更新：2026-11-15  
> 状态：**开发交接文件（SDD 初稿）**，不是全部剧情定稿  
> 使用对象：Claude Code / Claude Opus 等 AI Agent，以及项目创作者（负责逐步试玩、验收）  
> **首要规则：一次只做一个可验收的小步骤；用户亲自运行测试、明确批准后才允许下一步。**

---

## 0. 十条不可违反的规则

1. **平台战略：** 现在用 **macOS + Unreal Engine 5** 开发、运行、验证；未来主要发布 **Windows x64** 游戏。所有核心设计从第一天起必须考虑Windows兼容性，但现在不声称Windows已经验证通过。
2. **不能把预渲染视频当作剧情过场。** 游戏应当像《神秘海域》一样使用**实时3D角色、场景、灯光、动画和镜头**，支持从玩家操作无缝切入演出、再返回操作。
3. **绝对禁止连做多步。** 每个开发周期只交付一个最小、可运行、可人工检查的变更单元；完成后停止并等待用户明确说“通过/继续”。用户说“修改”则只修改当前步骤。
4. **先验证MCP，不能假设MCP已经能控制UE。** 必须实际测试连接、资产读写、场景保存、运行或测试能力。调用失败要报告事实，不能把仅写了说明当作完成。
5. **不允许自称已经测试或启动**，除非有实际UE运行/自动化测试/输出日志等证据。用户试玩属于单独的最终验收；Agent不能代替用户宣布通过。
6. **每一步先小后大。** 第一批步骤使用UE第三人称模板和基础灰盒资产；不要直接开始大量生成高精度角色、巨型关卡或整章剧情。
7. **不自行安装未经批准的第三方插件、模型或系统级软件**，不自行修改系统权限/安全策略；不能删除、覆盖旧工程、重置Git历史或破坏别的文件。
8. **以总交付成本为目标，而不是无限产出。** 跟踪步骤用时、Token/服务费用、失败次数和人工干预；尽量利用官方/可信素材、成熟组件和可复用模板。
9. **游戏中的北欧神话与原创改编严格分开。** 已明确未定的设定不可擅自当成正式剧情；不得复刻漫威或《战神》的原创造型、场景与对白。
10. **项目所有变更可追溯。** 每步有日志、测试说明、版本差异和回退方法；仅在用户批准后建立该步的正式Git提交（除非用户另外同意自动提交检查点）。

## 1. 项目概览与目标

| 项目 | 当前决定或目标 |
| --- | --- |
| 项目暂名 | LOKI / 《洛基》；正式名称未定 |
| 引擎 | Unreal Engine 5；先检查Mac已安装的**实际版本**，勿假设已是某一固定版本。未经同意不升级或覆盖 |
| 开发设备 | MacBook Pro M4 Max，128GB统一内存；macOS为当前实际开发/试玩环境 |
| 未来发行 | 以Windows x64为主要发行平台；可能经Steam发行，具体发行时间/渠道未定 |
| 当前开发目标 | 约2个月内做出能完整试玩的Demo（目标约10–15分钟；以可完成、可验证为第一原则） |
| 长期目标 | 希望6–12个月内发布短篇完整版；属于**有风险的时间目标**，不等于能够保证AAA产量和质量 |
| 建议首作范围 | 约60–120分钟、少数线性关卡、2–4名重点高精度角色、少量轻战斗与关键电影演出（建议上限，仍需用户确认） |
| AI/人分工 | Agent负责实际编程、UE编辑器修改、测试、记录；用户是导演、决策者和**每一步的试玩验收者** |
| 优先级 | 稳定可玩 > 可重复验证 > 剧情演出一致性 > 视觉精修 > 扩展系统与规模 |

### 一句话定位

**《洛基》是一款全实时3D、第三人称、线性单向推进的北欧神话叙事冒险游戏。** 核心体验约70%以上是角色关系、对白、潜行、身份伪装、谎言、环境互动和选择后果；轻度战斗是辅助，宏大神话奇观服务于人物冲突而非开放世界探索。

### 参考作品与边界

- 《神秘海域》：线性叙事、第三人称操作、自然衔接的实时3D电影镜头、边走边对话、只前进不反复清理世界。
- 《底特律：变人》：人物选择与后果，但不照搬复杂分支树；选择可分叉再汇合。
- 《瘟疫传说》：潜行、压力、同伴协作。
- 《战神4》：巨大生物、环境尺度、神话气氛；**不是**模仿其重度战斗和资产体量。
- 明确不做：GTA规模开放世界、魂类战斗、全图无缝探索、无穷装备成长、必须实时模拟的整座城市。

## 2. 核心故事与人物（已确定方向 vs 待定）

### 主题与主角

**主题：每一个谎言，终有一天要有人付账。** 洛基不是完全无辜的英雄。他可以真诚地关心他人，同时在决定性时刻为了自己的目的利用或牺牲对方；游戏不使用简单的善恶条衡量全部关系。

洛基与奥丁的关联主要是神话中的血盟/关系，不要写成漫威的养父子设定。他与安格尔伯达的三个孩子是芬里尔、耶梦加得、海拉。游戏**原创地**设定：奥丁因末日预言处置这些孩子后，洛基无力阻止，只能接受一个不平等协议，却暗藏漏洞，启动长期计划，既想改变孩子的命运，也想报复奥丁。

### 序章：两人越狱，最后一刻背叛（**基本确定**）

1. 开头洛基已被囚禁，大部分力量受抑制，失去原有物件；在逃亡中临时用废铁与布制作粗陋匕首。残余幻术/伪装能力有严格限度，不得靠无限洗脑解决剧情。
2. 洛基与另一名被囚的强大战士联手越狱。这名战争英雄有熊类战斗特征或能力、近战经验丰富，主要负责战斗；**名字、族群和熊化程度未定**（此前临时叫过“哈尔姆”“赫尔加恩”，不是正式名称）。
3. 两人多次互救、合作解谜和躲避守卫。洛基一直表现出值得信任的温暖、机智和体贴。**玩家应直到最后一刻才意识到背叛**，不能在前段用露骨邪恶表情剧透。
4. 在熔岩深渊旁，洛基利用换装/标记及幻术，让追兵误认同伴为洛基；自己伪装成同伴，突然将其推入深渊。追兵报告“洛基已死、尸骨无存”，但沿途熊爪伤痕指向逃亡的战士，导致同伴的身份遭通缉。洛基以这个被通缉身份逃出。
5. 背叛现场如何满足**两边伪装、见证者证词与追捕逻辑**，须继续严谨设计；不能只靠一句解释让计划毫无破绽。
6. 同伴未来可能以失忆/本能憎恨洛基的方式回归追债，**但目前与坠入熔岩毁尸的结局矛盾，尚未确定解决方法，不可擅自决定其存活**。

### 长线剧情（**方向确定，执行方式未定**）

- 洛基假死后联络旧日人情、秘密与被欺骗者，逐步接近奥丁的权力中心；他的孩子与复仇目标持续交织。
- 游戏原创地塑造巴德尔（Baldr）为少数真正影响洛基的人，让洛基在故事**后期、巴德尔死亡之前**开始考虑停止复仇；两人亲密关系并非神话原典事实。
- 在《散文埃达》相关版本里，巴德尔是奥丁与弗丽嘉之子；洛基主动利用槲寄生漏洞，引导失明的霍德尔击中巴德尔，造成死亡。游戏应保留洛基真实的主动责任，而非将死亡解释成与他无关的事故。
- 游戏目前考虑原创因果：洛基早年的谎言加深神族恐惧，后来他自以为能够控制一次槲寄生事件、逼奥丁让步，最终失去让他愿意收手的巴德尔。**假预言的具体内容、协议条款及事件机制尚未定稿。**
- 后续诸神决裂、正式束缚、诸神黄昏原则上尊重重要神话事件：芬里尔与奥丁、耶梦加得与索尔、洛基与海姆达尔的最终冲突。结局是否分支未定。
- **关键神话时间线：** 著名的洛基被捆绑、蛇毒滴落发生在巴德尔之死后；游戏序章的监狱应是**另一场更早的原创囚禁**，而不是直接挪用后期的惩罚。这个“双次囚禁”解释尚待正式批准。
- **第一章剧情尚未定稿。** 不可自动采用此前被否定的“雪地饥饿、寡妇、泛泛巨人战争或无关Boss”等方案。

### 开发中的故事处理规则

- 不因程序方便改变关键人物关系、背叛时机或主题。
- 新增剧情只允许作为**提案**，列出和现有神话/前文冲突的地方，待用户批准后入主设计文档。
- **初期开发只做已确定的可测玩法和序章片段**。不要提前制作未定第一章、巴德尔或诸神黄昏关卡。
- 本文件末尾的**附录A**完整保留先前的创作记录，包括曾否决方案及待解决逻辑题；在写新剧本前必须阅读。

## 3. 玩法系统：小而完整

| 系统 | MVP要求 | 暂时不做 |
| --- | --- | --- |
| 移动视角 | 第三人称行走、奔跑、简单互动、基础相机 | 复杂跑酷与多套攀爬动作 |
| 潜行 | 守卫巡逻、基础感知/警觉、绕行或诱导、被发现的简单后果 | 全地图综合警戒生态、复杂群体协作AI |
| 幻术 | **仅一种能力**：短时诱饵/视觉干扰，可用于解谜与潜行，限制次数或冷却 | 无条件任意变身、完全读心/操纵所有NPC |
| 轻战斗 | 一个简单近战攻击、受击、生命与死亡/失败、撤退选择 | 精密格挡、魂类Boss、连招树、RPG装备系统 |
| 同伴 | 指定位置跟随、配合互动、少量剧情动作 | 通用全场景战斗伙伴AI |
| 对话 | 少量分支、条件与剧情标记、字幕 | 海量对话树、复杂声望系统 |
| 检查点 | 失败重试、每段场景合理重置 | 开放世界全局存档系统 |
| 演出 | Sequencer实时3D镜头，播放后恢复控制，同角色同场景 | 任何预录视频/AI生视频直接作为过场 |

### Demo建议路径

**牢房 → 守卫通道 → 幻术/潜行 → 同伴协作 → 熔岩出口 → 背叛实时演出（有条件地进入最终Demo）。**

前几周先做**灰盒2–3分钟可玩闭环**；第8周目标升级为可展示的10–15分钟Demo。若人物动画和演出成本超预期，应保留短而完整的高品质可玩切片，不得用无法运行的大而全内容冒充Demo。

## 4. 美术、场景及性能原则

- **写实、电影化、阴郁神秘、北欧神话尺度感。** 场景规模比GTA小得多，玩家原则上只前进、不返回上一大区域。
- 每章拆分小型可玩区，进度推进后按设计卸载旧区；分镜之外的大部分建筑和远景无须具备真实交互能力。
- 近景（玩家和可接触物件）精细；中景采用LOD/HLOD、遮挡剔除和合理碰撞；远景采用简化网格、Impostor、静态景片/背景地形、预设动画、雾与透视构图。**不要把远景展示图作为预渲染视频播放。**
- 优先复用经过验证许可的模型、材质、音频和动画；不得自动下载需要登录的付费资产、盗版、商用授权不明的内容。
- **大生物**可以通过局部模型、分镜、远景代理、预设动画制造尺度感；不要求一开始就有完整寻路与交互的大型Boss。
- **统一主角资产**：实时演出与实际玩法使用同一套人物网格/材质/装束配置，减少镜头切换不一致。
- 角色表情、肢体接触、对白节奏和角色之间的准确互动是长期主要制作难点，不因场景缩小而自动解决。
- 画质设置从一开始规划低/中/高可扩展性；不强制依赖硬件光追或Windows专属图形功能。Mac上的某些UE高级特性有平台限制，实际功能以安装版本测试为准。
- **不把Mac测试FPS当成Windows性能结论。** 每轮可记录Mac分辨率、渲染比例、FPS和异常；Windows平台到手后单独验证。

## 5. 技术架构与Mac→Windows原则

### 5.1 环境与版本

1. 开始只做**只读环境盘点**：macOS版本、UE实际版本、引擎路径、现有项目路径、Claude Code版本、MCP服务器列表与对应可用工具。
2. 在接到用户授权之前，不自行安装/升级UE、不覆盖现有项目、不删除任何旧项目。
3. 新建专用独立测试工程（用户选择路径），建议项目代号 `LOKI`；如果用户已经有工程，优先询问是复用还是新建。
4. 当前Mac原生编译、编辑器Play-In-Editor与macOS构建是每个阶段的基本验证通道。
5. 以后Windows x64是最终目标，但**Mac上普通UE工程不能直接按常规流程打包Windows .exe**。未来需接入真实Windows构建环境，保持引擎和插件版本一致。

### 5.2 源码与资产

- 游戏核心逻辑优先使用**易读、易测的UE C++模块或经验证的Blueprint**；数据驱动剧情、配置和关卡。不要为了“只写C++”而让开发效率明显下降。
- 需要编辑Blueprint、Level、Sequencer、Material等二进制资源时，Agent必须使用**真正可调用的UE编辑器/MCP/Python API**并检查资产已保存，而不是虚构出不存在的节点或把伪代码当资源。
- 不要让两个Agent并发编辑相同的 `.umap`、`.uasset` 或同一组Blueprint资产；需要并行时使用分支/worktree并序列化资产合并。
- 优先UE标准输入、UI、存档、动画、Audio组件；避免无理由添加平台特定依赖。
- 路径统一使用UE的相对内容路径、`FPaths`、项目/插件目录，不硬编码 `/Users/...`、Windows盘符或大小写敏感假设。
- C++代码考虑Clang（macOS）和MSVC（Windows）的编译差异；仅在确有需要时使用明确的平台条件编译。
- 第三方MCP插件原则上应属于**编辑器开发工具**，**不能成为打包游戏运行时必需依赖**；以后Windows Build时要检查插件目标平台和模块类型。
- 使用Git跟踪代码和配置；大型二进制美术资产需要Git LFS或其他可靠的大文件管理。不要提交 `Saved/`、`Intermediate/`、`DerivedDataCache/`、临时Build等。

### 5.3 自动测试与交付物

每步尽可能附带下列可复现证据（不支持的能力须如实报告）：

- 操作前后更改的文件/资产清单、具体引擎Content Browser路径。
- 成功保存场景/资产的确认信息。
- 编辑器启动情况、PIE运行情况、相关日志和明确错误。
- 脚本或自动化测试执行结果（若适合当前步骤）。
- 可让用户**实际自己打开并测试**的路径与按键步骤。
- 存在平台限制时注明“Mac已验证 / Windows尚未验证”，不以CrossOver代替Windows本机测试。

## 6. MCP连接：先实测再开发

**第0个开发步骤只做检查，不改项目：**

1. 用真实终端操作检查实际UE路径/版本及MCP服务器启动方式；列出当前Agent能够调用的工具名称，而不是凭网上教程声称具备功能。
2. 若连接缺失，说明至少一种官方/可信社区候选方案的来源、平台支持、维护状态、权限与安装命令，**等待用户同意后才安装**。
3. 在用户批准的空白测试工程中做最小写入验证：创建简单场景，添加一个Cube，保存，关闭再打开确认仍存在；随后执行Play或其它可用的实际检查。
4. 如果MCP不能完成某项操作，可以申请使用UE Python Editor Scripting、C++、命令行等**有证据的替代路线**，但仍须在编辑器里验证成功。不能声称通过MCP做到了实际是没做的事情。
5. 连接验证成功后，**停止等待用户验收**，而不是直接开发战斗或剧情。

## 7. 严格分步迭代协议（必须遵循）

### 一次仅一小步

每次收到“继续/通过”后，AI应选择**当前里程碑中的一个最小可验收事项**，例如“WASD移动”“能打开对话界面”“守卫沿两点巡逻”。绝不同时加入战斗、剧情、材质、音效等多个不相关功能。

**每一步的执行顺序：**

1. **说明本步：** 一句话说明要改什么、验收点是什么、预计影响哪些资产。
2. **最小改动：** 通过可用MCP/API/代码真实操作UE并保存；不得越界修改下一阶段。
3. **Agent自测：** 尽可能运行UE、看日志/自动化测试；如失败，先在当前步骤内修复并重新验证。
4. **交付用户可测版本：** 明确工程路径、打开方式、按键与观察点；必要时提供准确命令。
5. **停止等待：** 明确写 **「当前步骤已提交验收，等待你亲自运行测试。未经你确认，不进行下一步。」**
6. 用户反馈 **“通过”** → 记录通过、请求或执行受权Git提交并进入下一个小步；用户反馈 **“有问题”** → 只修当前步；用户反馈 **“暂停”** → 不继续修改。

## 01｜创作定位（基本确定）

- **类型：** 第三人称、电影化互动叙事冒险，以剧情和人物关系为主；辅以轻度战斗、潜行、伪装、诡计和环境探索。参考《底特律：变人》的分支与后果、《瘟疫传说》的潜行和《战神4》的神话尺度感，但不直接复制任何一款作品。
- **技术与规模：** 面向 Unreal Engine 5；尽量通过 AI Agent、Blueprint、AI 辅助概念设计／3D 制作完成；由创作者审核关键剧情和画面。先制作高完成度可玩 Demo，再决定完整游戏规模。
- **战斗定位：** 战斗要有戏剧张力，但不是以魂类 Boss 难度和极致打击手感为核心卖点；不以不停刷怪、升级、提升数值作为主要循环。可以有少数难忘的战斗、逃亡和大型神明遭遇。
- **核心玩法：** 玩家通过了解他人的秘密、选择说真话或谎话、伪装身份、制造幻象以及利用环境完成目标。「情报」比装备等级更重要。复杂多分支需控制制作规模，优先有限但有后果的选择。
- **视觉方向：** 阴郁、神秘、宏大；九界、古神、巨人、芬里尔、耶梦加得等可以制造世界之蛇级别的震撼，不一定都必须成为可击败的 Boss。
- **版权原则：** 基于公有领域的古北欧神话文本和原创设计；避开漫威及《战神》独有的造型、情节和对白。尽量尊重古代神话主要人物关系和大事件，同时允许在史料空白处创作。

## 02｜一句话故事与主题（方向确定，具体结局未定）

**一句话故事：** 被诸神夺走孩子、又遭囚禁的诡计之神洛基，以欺骗和旧日人情重返诸神的权力中心；当他终于可能放弃复仇时，自己过去布下的谎言却害死了唯一使他愿意收手的人，最终把自己和九界推向诸神黄昏。

**中心命题：** 「每一个谎言，终有一天要有人付账。」

洛基不必是传统的好人。他会鼓励别人、关心别人、甚至愿意冒险去救人；但也能在关系最亲密的时候，为保全自己把对方推向死亡。他会为一些事情难过，但不意味着下一次就不再利用别人。**不要把故事写成简单的善恶值、积德行善或固定的洗白成长。**

**宏观主题：** 自由的代价、命运的预言、被拆散的亲情、权力的恐惧、过去的谎言回返，以及「当一个人永远把别人当棋子，他终会被自己的棋局困住」。

## 03｜神话基础：哪些是原典、哪些是原创

### 原典依据：主要参考《诗体埃达》《散文埃达》

1. **洛基**是与巨人有亲缘关系、常与诸神同行又多次破坏他们利益的复杂人物。他善于欺骗、变化形态；不是漫威版本里奥丁的养子。相关文本没有给出一部完整统一的「洛基自传」，故事年代与细节未必完全一致。
2. **奥丁**是诸神之父，洛基在《洛基的争吵》等文本中谈及与奥丁的结义／血盟关系。二人关系不能简单化为现代影视里的父子。
3. **洛基与安格尔伯达（Angrboða）的三个孩子：** 巨狼芬里尔（Fenrir）、世界之蛇耶梦加得（Jörmungandr）、亡者国度的海拉（Hel）。奥丁因预言担忧而对三者采取控制措施：芬里尔受束缚，世界之蛇被抛入海洋，海拉被交付亡者国度。提尔在芬里尔被束缚时失去一只手。
4. **巴德尔（Baldr）不是洛基的儿子。** 他是奥丁和弗丽嘉的儿子。在《散文埃达》的著名版本里，洛基得知槲寄生不在不伤害巴德尔的誓言之列，利用失明的霍德尔（Höðr）将槲寄生射／投向巴德尔，致其死亡。原典没有明确说巴德尔和洛基是最好的朋友，也没有给出一个完全无争议的现代心理学式动机。
5. 巴德尔之死后，诸神试图把他从亡者国度带回；在《散文埃达》版本中，拒绝为巴德尔哭泣的女巨人通常被认为与洛基有关。洛基后遭追捕、被捆绑在岩石上，蛇毒滴落，妻子西格恩（Sigyn）用容器接毒。到诸神黄昏，他挣脱束缚，站在诸神敌对一方，最后与海姆达尔（Heimdallr）互相杀死。
6. 预言里，芬里尔吞噬奥丁，耶梦加得与索尔同归于尽。**原始神话并没有明确说洛基发动诸神黄昏是为了营救三个孩子**，这一动机属于游戏原创解释。

### 游戏的明确原创改编

- 洛基曾在早年为孩子与奥丁达成**不平等交易**，并暗中保留条款漏洞，谋划多年。这不是现存神话明文叙述。
- 巴德尔在游戏中可能成为洛基真正珍惜的朋友、让他想停止复仇的人；这段亲密关系属于原创。
- 过去为保护孩子而作的某个谎言，间接造成后来的槲寄生漏洞；洛基随后为「可控地制造事故以逼奥丁退让」仍**主动引导霍德尔**，却造成巴德尔死亡。这是为兼顾原典事件与游戏人物弧线而讨论出的原创因果。
- 越狱序章、熊型盟友、熔岩假死、相关通缉与后续复仇追债均为原创。

> **重要时间线警告：** 古代神话中最著名的「洛基被石头绑住、蛇毒滴落」发生在巴德尔之死及诸神决裂之后；我们游戏想把一次越狱放在巴德尔之死之前。若坚持贴合主要原典事件，序章必须解释为**另一次、较早的原创囚禁**，不能误当原典那一次最终蛇毒刑罚。后期仍应保留巴德尔之死 → 诸神追捕 → 原典蛇毒束缚 → 诸神黄昏的顺序。这个「两次囚禁」方案尚待正式确认。

## 04｜已反复讨论并基本认可的序章：《死人不需要名字》（章节名暂定）

### 起点与角色状态

洛基遭到囚禁（原因、地点、时间必须在后续补全；见第 03、08 节）。经过漫长的囚禁，他的大部分神力遭到封锁或极度衰弱，原本的武器、神器已经不在身边。他没有可以一击秒杀守卫的超强法术，也无法靠武力强闯。他在逃亡路上临时用**碎铁／金属碎片与破布**制作了一把粗陋的匕首；这**不是找回他本来的匕首**，也不是忽然恢复力量的神器。

洛基仍保留**少量幻术、外貌伪装及蛊惑／影响人判断的能力**，具体边界尚未定稿。原则：不能靠无代价、无限强度的精神控制解决全部问题，最终背叛的说服力主要来自长期建立的信任。

### 盟友（姓名与身份尚未确定）

序章中洛基与另一位囚犯共同逃亡。该盟友应当是一位**曾经的战争英雄／强大的战士**，性格中有强烈的荣誉感，拥有在近身搏斗中占优势的蛮力，可考虑具有**巨熊、熊化或兽性战斗**的特征。之前临时用过「哈尔姆」和「赫尔加恩」等名称，**都没有最终确认**，不要视为正式神话人物。

这位盟友并不天真，也未必可靠；恰恰因为他被世界抛弃、习惯遭怀疑，才尤其渴望有人真心信任他。他在战斗中冲在前面，击倒大多数守卫；沿途留下无法伪造的熊爪、重击、破碎甲胄等独特创伤痕迹。

### 共同逃亡：必须把「信任」做得真实

序章的情感核心不是玩家一眼看出洛基是坏人，而是**玩家也在最后一刻才知道背叛**。

洛基一路和盟友配合得极好。他聪明地规划路线、想办法破解机关；盟友负责最危险的肉搏。洛基不断鼓励他，维护他的尊严，像一个善良、体贴、懂得感恩的朋友。二人应当真正完成多次漂亮配合，彼此救过对方；洛基甚至可以有让人难以判断真假、看起来发自内心的照顾。玩家理应在情感上认同这段搭档关系。

**重要体验原则：** 别在背叛前安排太多露骨的「洛基冷笑」「邪恶眼神」提示，避免削弱最后一秒的反转。最好的伏笔，是玩家事后回想才发现其双关意义的承诺和动作。

### 终点：熔岩深渊上的背叛

来到最后的出口时，身后的守卫追至。盟友遍体鳞伤，却认为两人终于要一起得到自由。出口附近是一片致命的**熔岩池、火海或其他具有彻底毁尸效果的深渊**（场景类型未定）。

洛基利用盟友对自己的信任，借伤势、换装或掩护之名把自己的衣物／身份标记交给对方，并利用残存幻术让对方被追兵看到时**像极了洛基本人**。在盟友完全没有防备的瞬间，洛基将他推／踢入深渊，然后自己**伪装成那名盟友**逃离现场。

守卫赶到时，亲眼看见「洛基」消失在无法寻回尸体的火海里，于是上报：**洛基已死，尸骨无存。** 众神不再按洛基本人展开公开追捕。与此同时，沿途死去的守卫身上都有那位战士特有的熊爪伤或暴力创伤，官方把杀戮归在**那个『逃掉的战争英雄』**头上，开始通缉这个身份——也就是洛基此刻正冒充的人。

玩家此刻才发现：自己操控的真实主角一直是洛基，眼前所谓的完美搭档只是被用来获得自由、制造假死、转移罪名的牺牲品。

**序章要达成的双重效果：**
1. 洛基在公开记录里「已经死了」，可以暂时在诸神视线之外活动。
2. 他的自由从第一步就建立在一笔无法抹去的债上，逃亡之后还要利用被通缉的盟友身份求生。

### 序章反转的视听与操作表达（未定稿建议）

为保留「玩家直到最后一秒都不知情」，前段让两人共同执行各种小型诡计；最后一刻将动作置于不可完全预知的剧情镜头，而不是提前提示「按键背叛同伴」。镜头从坠落者身上转回逃亡者的脸，一瞬间出现洛基真实面貌／幻术褪去，再让守卫高喊「洛基死了」。此设计只是可考虑的演出方案。

## 05｜序章之后：目前仅确定的原则，第一章剧情尚未定稿

**已确定：**
- 洛基假死后应有更大规模的世界和事件，而非只有普通雪地求生。
- 游戏必须兼顾剧情、战争的阴影、神祇的压迫感、特殊遭遇和适量战斗／Boss，但**不能用毫无因果的巨型战争、凭空冒出来的 Boss 来堆所谓宏大**。
- 第一章需要和序章的背叛、盟友留下的伤痕与「被通缉的身份」、洛基的过去以及失去的孩子形成紧密因果。
- 神话大事件需尽量尊重原典的时间线；编造内容必须标注原创。

**曾提出但用户不满意／尚未采纳的第一章方案：**
1. 洛基在雪中走两天、饥饿、被寡妇收留，仅用通缉告示推动剧情——**被指出不够精彩且不属于原典，不应当成正篇**。
2. 边境小规模巨人战争加原创「誓约守卫」Boss——**不够宏大**。
3. 世界树裂开、冰霜巨人全面战争、海姆达尔在符文桥上作为 Boss——**视觉大但与人物因果结合不足，未获认可**。
4. 用全盛时期战争闪回和现世牢狱形成对比——**未获认可**。
5. 洛基逃亡后与提尔并肩探索芬里尔封印的秘密、面对一位神话级敌人——只是一项方向性建议，**未得到具体剧情确认**。
6. 港口酒馆、渡鸦、海里耶梦加得对洛基说话——曾讲过的即兴片段，**没有被确认**，不得直接当作定稿章节。

**目前第一章正确状态：空缺，必须从原典与人物关系重新设计。** 不需要假装已经写好。

## 06｜全局主线：已经形成的主要方向

### 过去：无力救孩子，秘密启动一盘长棋

在我们的原创版本中，洛基当年亲眼看见奥丁因诸神黄昏预言而对他的三个孩子采取行动：芬里尔被束缚，耶梦加得被放逐到大海，海拉被安排去掌管亡者的国度。当时洛基不是不想反抗，**而是确实无能为力**。

为了尽可能保住三个孩子的性命，他被迫与奥丁订立某种不平等协议；但洛基在协议／承诺中偷偷藏下一个漏洞，并在往后多年里埋下利用人际关系、谎言、交换承诺的长期计划。这条「协议及漏洞」为原创剧情，具体条文、真正代价、奥丁为什么接受都**尚未写出**。

他表面上仍与诸神周旋，时而帮他们摆平麻烦，时而制造更大的问题；暗地里积累某种在未来让奥丁失去一切的能力。他既想挽回三个孩子的命运，也想让奥丁付出代价。**救孩子与复仇并非永远一致，后期必须发生冲突。**

### 现世：赢得自由，却背负更多旧债与新债

洛基在假死逃亡后，需要重新接触多年以前被他救过、欠过他情、或遭他利用的人；通过自己的名字、假身份、秘密和人情，一步步回到诸神权力网络的中心。重要的不是一味恢复战力，而是重新布置人际关系和局势。

每一次欺骗都有实际后果：有些人被出卖、有些人逃脱、有些人失去亲友；这些后果会在之后的章节「回来找他」。洛基不立刻悔改，反而可能继续考虑**如何利用追债者**。玩家不需要操控一个越来越善良的英雄。

### 后期重要拐点：巴德尔让洛基动摇

**用户偏好：** 洛基真正开始想放下复仇，应当出现在故事较后段，**并且在巴德尔之死和诸神公开羞辱洛基之前**。

我们原创地将巴德尔塑造成奥丁之子、温和而值得信任的人；他不一定天真，也不只是说教，他确实接纳过复杂的洛基。两人的相处让洛基第一次认真考虑：也许不必把所有人推向战争，也可以找到另一条路保全孩子、获得安宁。

这里必须保留洛基的道德矛盾：他可能真心想停，但**没有勇气清理旧谎言，也不肯完全放下自己控制局面的习惯**。

### 巴德尔之死：不是简单的意外，而是旧谎加新的主动算计

为了尽量保留《散文埃达》的关键情节，我们已讨论以下因果：

1. 多年前，洛基为救孩子制造的某个**假预言／欺骗／秘密操纵**，间接加深了奥丁对失去巴德尔的恐惧；弗丽嘉为保护巴德尔，寻求万物不伤他的誓言，却漏掉了槲寄生。（与原典的因果连接为**原创**，仍需精修。）
2. 到故事后期，洛基已经受巴德尔影响，真的开始想放弃复仇，但依然保留了想向奥丁施压的最后一招。
3. 洛基发现槲寄生的漏洞，**明知道这可能伤到巴德尔**，仍试图制造一场自己认为「可以控制后果」的伤害，作为逼迫奥丁退让的筹码。
4. 他主动引导失明的霍德尔以槲寄生击中巴德尔，结果巴德尔真正死亡。**主动引导霍德尔这一关键行为必须保留**，不能把所有责任推给旧谎言或巧合。
5. 洛基最终亲手失去了使他愿意收手的人。旧计划、新算计与不肯放手的控制欲，共同把他推到不可挽回的一步。

这不是「巴德尔被随机事故杀死」；也不能写成「洛基本意只想给巴德尔开玩笑，因此完全无辜」。玩家应当能理解他、同情他的失败，但也能看出**他对此负有真正责任**。

### 最后的裂痕：被羞辱、正式受缚，走向诸神黄昏

巴德尔死亡后，洛基与诸神之间的关系彻底破裂。剧情计划利用原典中的《洛基的争吵》（Lokasenna）及后来的捆绑刑罚，在公开羞辱、相互控诉和对旧账的揭露中，让洛基失去最后的退路。这里不能把洛基写成只会被别人欺负的无辜者；他的选择确实造成灾难，诸神也可能出于恐惧、尊严和权力做出残酷选择。

最终，他与众神敌对，走向诸神黄昏。尽量保留已知的神话结局：芬里尔与奥丁、耶梦加得与索尔、洛基与海姆达尔的宿命冲突。**游戏到底是固定悲剧结局、有限多结局，还是允许玩家付出巨大代价改变部分命运，尚未定。**

## 08｜必须解决的连续性和逻辑问题（尤其重要）

1. **两次囚禁如何相容？** 序章发生在巴德尔之死前，而《散文埃达》里著名的毒蛇刑罚在死后；序章要改为另一种原创囚禁，并说明当时奥丁为什么囚禁洛基、为什么放出一个熊型战士等。**不能直接用原典蛇毒刑罚当作序章又不解释后面的第二次刑罚。**
2. **序章盟友到底死没死？** 用户喜欢他今后「回来追债」，更喜欢一种「记忆残缺，但见到洛基便本能憎恨，洛基却还想先利用他」的关系；但序章又明确把他踢进可以毁尸的熔岩火海。必须决定他是确实死亡、由神话机制复归，还是坠落并非真死，或是另一个人承继这笔债。**目前没有定案，不可贸然写成存活。**
3. **幻术强度与假死证据：** 洛基明明被封印，为何还能让一个人被守卫认成自己、同时把自己变成熊型战士？这两种效果是否限于短时间、特定光线、临时身份标记或守卫的主观误认？须建立严谨规则，避免前后矛盾。
4. **盟友的身份是否经得起通缉调查？** 现场「洛基坠火而死」和「熊型战士留下杀戮特征逃走」应有可相信的证据链；不能只靠守卫一句话。洛基之后长期伪装成被通缉的盟友，为什么仍能行动？必须有合适的行踪／换身份机制。
5. **孩子与时间顺序：** 孩子什么时候被奥丁处置？洛基何时订约、撒假预言、遭第一次囚禁？与巴德尔之死、弗丽嘉求誓言之间应建立可视化年表。
6. **巴德尔的原典责任不能稀释：** 游戏允许洛基认为事情可控，但仍须主动递出槲寄生并引导霍德尔；否则「尽量贴近神话」的承诺落空。
7. **洛基与巴德尔何时建立友谊？** 需要足够长的共同冒险，才能让「愿意收手」与「亲手失去精神支柱」可信，不能靠几段台词突然成立。
8. **第一章真正的目标与戏剧事件：** 既要大场面，也要从序章的背叛和洛基的旧谎自然生长；用户已多次否决无因果的战争与空洞 Boss 堆砌。
9. **玩家决策范围：** 序章背叛暂定是作者控制的剧情反转；之后哪些决定可改变人物命运、哪些神话大事件必须固定，应写入分支图。不要以「玩家有选择」为由承诺无限分支。

## 09｜按现有信息排列的暂定时间轴

> 注意：这是创作结构草案，不是古北欧神话的统一古代年表。

1. **过去：** 洛基与诸神往来；三个孩子的存在引发奥丁恐惧。诸神分别处置芬里尔、耶梦加得、海拉。
2. **过去：** 洛基无力阻止，签不平等约定，暗藏漏洞；展开长期计划并制造某个关键谎言。
3. **序章前：** 洛基因**尚未决定的原因**遭到第一次（原创）囚禁，力量被封，神器被夺。
4. **序章：** 与熊型战争英雄逃狱，长期友好搭档，熔岩处突然背叛，洛基假死、顶替盟友逃走。
5. **第一章至中盘：** 尚未定稿。需具体讲述他如何在通缉身份之下，逐步联系旧人、旧承诺与孩子。
6. **中后段：** 巴德尔成为能影响洛基的人，洛基一度认真考虑停止复仇；时间安排在巴德尔之死前。
7. **后段：** 旧谎言推动槲寄生漏洞，洛基新算计试图施压奥丁，主动引导霍德尔，巴德尔死亡。
8. **后段：** 洛基与诸神公开决裂、在宴会上相互攻击，随后遭原典式捆绑、蛇毒之罚。
9. **终章：** 诸神黄昏；主要宿命事件原则上遵循神话，游戏结局的玩家选择空间待定。

## 10｜开发转化原则（非正式玩法文档）

- **序章可玩体验：** 与盟友协作战斗、洛基的小诡计／机关互动、互相鼓励和剧情选择、最终无法预见的背叛反转；动作难度不宜盖过叙事。
- **强者与弱者对比：** 序章主要由盟友承担正面战斗，洛基依赖欺骗、地形和时机；这能解释他为何需要盟友。
- **身份系统：** 在严格限定关卡内实现伪装／被识破，而不是无边界的全世界任意变身系统。
- **谎言的债务：** 不用简单善恶值；以人物关系、被追捕身份、旧承诺、发现的秘密和迟到的后果体现。
- **神兽巨景：** 芬里尔、世界之蛇可以是剧情节点、活着的地形与可交互的威胁，不必制作成复杂全动态 Boss。
- **核心优先级：** 剧情因果与人物可信度 > 单纯规模；惊人的视觉奇观应当有情感与情节意义。
